# Run token usage

Relay exposes provider-neutral token usage through `usage.updated` events and `Run.usage`. Node normalizes native runtime events; API clients do not need to understand provider accounting. This is an additive protocol extension. Older Nodes simply do not report usage.

## Wire contract

```json
{
  "type": "usage.updated",
  "attempt_id": "attempt-1",
  "data": {
    "input_tokens": 1200,
    "output_tokens": 200,
    "total_tokens": 1400,
    "cache_read_tokens": 900,
    "cache_write_tokens": 0,
    "reasoning_tokens": 50,
    "status": "complete",
    "source": "codex",
    "model": "configured-model"
  }
}
```

Each event is an **absolute snapshot for one execution attempt**, never a delta. Input includes cache reads and writes; output includes reasoning. Cache and reasoning fields are subsets, so total is input plus output. Omitted fields mean unknown, including model when the runtime selected its default. Zero is an actual reported zero.

`partial` means the known usage may be incomplete; `complete` means the adapter observed final input/output accounting for this attempt. This is runtime-reported usage, not a billing guarantee. Cancelled/failed attempts keep known partial consumption. Run queries sum the latest snapshot per attempt, including retry attempts. Missing attempts lower the aggregate status to partial. Neither duplicate event delivery nor repeated queries add consumption.

Usage events use the existing durable PostgreSQL event log, indexed by Run/attempt/sequence. Successful execution results also contain `result.usage` for the last attempt. The top-level `Run.usage` aggregates all observed attempts. Failure/cancellation still exposes usage through the event log even without a successful Result.

## Runtime normalization

| Runtime | Input source | Accounting |
| --- | --- | --- |
| Codex / Trae exec JSONL | `turn.completed.usage` | Invocation snapshot; cached input is already included |
| Codex / Trae app-server | `thread/tokenUsage/updated` | Restore baseline and current thread/turn scope; subtract thread cumulative baseline, never sum cumulative notifications |
| Claude Code | `assistant.message.usage`, final `result.usage` | Deduplicate assistant message IDs; final invocation result replaces intermediate totals; add separate cache reads/writes to uncached input |
| Pi | `message_end.message.usage`, `agent_end` | Deduplicate message timestamp/ID; sum assistant messages from this invocation; input excludes separate cache fields |
| OpenCode | `step_finish.part.tokens` | Deduplicate part IDs; input excludes cache, output excludes reasoning; add each exactly once |
| Qoder / QwenWork | Unverified | Remain unreported; no guessed token counts |

Codex/Trae app-server fields were checked against schemas generated by the installed CLIs. OpenCode's input/output separation matches `packages/core/src/session/usage.ts` in upstream. Tests use representative protocol fixtures, fake executors and real PostgreSQL; they do not issue billed model requests or establish end-to-end compatibility with every CLI release.

When a resumed app-server does not emit restored usage, the first current notification's `total - last` supplies the baseline. A counter reset preserves the already known lower bound and marks it partial. Unknown/malformed usage is ignored. Original native events remain available for diagnostics.

## Deployment

Build and upgrade Relay Server **and Relay Node** to enable this code. Server migration `011_usage_events.sql` adds the usage event index. Nodes using the old build will not emit normalized usage. No credentials or native session configuration changes are required.
